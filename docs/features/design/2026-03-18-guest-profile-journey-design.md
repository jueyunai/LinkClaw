# LinkClaw 嘉宾个人画像流程重组设计

> 日期：2026-03-18
> 范围：嘉宾个人画像入口、保存回跳、个人中心承接与首页引导重组

## 目标

解决当前嘉宾个人画像流程中的三个核心问题：

1. 保存画像后仍停留在编辑页，缺少回到主流程的承接。
2. 个人画像只有首页临时入口，填写完成后缺少长期稳定入口。
3. 嘉宾 onboarding、日常维护与推荐体验之间没有形成闭环。

本轮目标是在不重做整套路由架构的前提下，把个人画像从“首页一次性临时入口”升级为“个人中心内长期存在的固定模块”，并让首页只承担首次引导与持续提醒职责。

## 已确认产品决策

### 信息架构

- 首页：负责活动发现与个人画像引导。
- `/my-events`：升级为统一个人中心。
- `/profile`：保留为个人画像编辑页。
- 导航栏用户名入口继续进入 `/my-events`。

### 角色策略

- 嘉宾：首次进入时有明显画像引导，个人中心顶部存在固定画像模块。
- 主办方：仍以活动管理为主，不把个人画像作为主任务区。

### 回跳策略

- 保存后遵循“从哪进回哪去”。
- 从首页进入编辑页，保存后回首页。
- 从个人中心进入编辑页，保存后回个人中心。
- 来源参数缺失或异常时，默认回个人中心。

### 首页引导策略

- 首次为强提醒。
- 后续未完善时降级为弱提醒。
- 已完善后隐藏首页主提醒。
- 长期固定入口转移到个人中心。

### 个人中心展示策略

- `/my-events` 对嘉宾升级为统一个人中心。
- 嘉宾版顶部第一块即为“个人画像”主卡片。

## 当前问题与根因

### 1. 保存成功后的页面承接错误

`updateProfile` 目前固定在成功后跳回 `/profile?success=true`，导致编辑页同时承担“编辑”和“结果承接”两种职责，用户保存后不知道下一步做什么。

涉及文件：
- `src/app/[locale]/profile/actions.ts`

### 2. 首页入口是一次性临时能力

首页当前会在画像未完善时显示提示卡，但当画像完善后该入口就消失，用户缺少长期稳定的再次编辑入口。

涉及文件：
- `src/app/[locale]/page.tsx`

### 3. 个人中心没有承接个人画像能力

当前 `/my-events` 已按角色区分嘉宾/主办方内容，但嘉宾页只展示报名与邀请，没有把个人画像纳入稳定信息架构中。

涉及文件：
- `src/app/[locale]/my-events/page.tsx`
- `src/components/layout/navbar.tsx`

## 设计原则

- 编辑页只负责编辑，不负责结果承接。
- 首页只负责首次引导和持续提醒，不承担唯一入口职责。
- 个人中心负责长期承接和固定入口。
- 同一路由按角色展示不同主模块，不做无关大重构。
- 画像完整度判断规则必须统一，避免首页和个人中心出现不同结论。
- 在现有 App Router + Server Action + redirect 模式上最小复杂度落地。

## 用户路径设计

### 1. 嘉宾首次完善路径

1. 嘉宾登录进入首页。
2. 如果画像未完善，首页显示强提醒卡片。
3. 用户点击“去完善个人画像”，进入 `/profile?from=home`。
4. 编辑页读取 `searchParams.from`，仅接受 `home | center` 两个合法值，并将规范化后的 `from` 通过 hidden input 或等价方式透传给 `updateProfile`。
5. 用户保存画像。
6. 保存成功后回到首页。
7. 首页显示成功反馈。
8. 后续如需修改，用户可从个人中心顶部固定入口进入编辑页。

### 2. 嘉宾后续维护路径

1. 用户进入 `/my-events`。
2. 顶部个人画像卡片展示当前状态。
3. 点击“编辑画像”，进入 `/profile?from=center`。
4. 保存成功后返回 `/my-events`。
5. 个人中心显示成功反馈。

### 3. 主办方路径

- 主办方仍通过 `/my-events` 进入工作台。
- 页面仍以活动管理为主。
- 个人画像不进入顶部主任务区，避免干扰主流程。

## 页面结构设计

### 首页

#### 嘉宾未完善画像

首页在推荐区前保留引导区块，但分成两种展示强度：

- 强提醒：首次登录后或首次进入主流程时出现，强调完善画像可提升推荐与邀请匹配效果。
- 弱提醒：用户已看过提醒但仍未完善时降级展示，继续保留编辑入口但不占据主视觉。

#### 嘉宾已完善画像

- 首页隐藏主提醒卡。
- 页面聚焦推荐结果与活动浏览。
- 若为刚从编辑页保存返回，则顶部显示一次成功提示。

#### 主办方

- 不展示画像引导逻辑。
- 保持当前首页主流程。

### 个人中心 `/my-events`

#### 嘉宾版结构

页面顺序调整为：

1. 个人画像主卡片
2. 我的报名
3. 我的邀请

个人画像主卡片需包含：
- 标题：个人画像
- 状态：已完善 / 待完善
- 描述：说明画像用于推荐与邀请匹配
- CTA：未完善时显示“去完善”，已完善时显示“编辑画像”

#### 主办方版结构

- 保持活动管理为主。
- 页面文案从“我的活动”增强为更像“个人中心 / 工作台”的语义。
- 顶部仍显示身份信息和创建活动入口。
- 本轮不把个人画像作为顶部主模块。

### 编辑页 `/profile`

- 保留当前表单结构。
- 页面职责明确为“编辑个人画像”。
- 页面文案强调画像会影响推荐和邀请匹配。
- 成功后不再停留本页承接结果，失败时才留在本页并展示错误信息。

## 状态与参数流设计

### 1. 来源参数

编辑页支持来源参数：

- `from=home`
- `from=center`

入口规则：
- 首页引导入口跳转至 `/profile?from=home`
- 个人中心固定入口跳转至 `/profile?from=center`

编辑页必须读取 `searchParams.from`，并将规范化后的来源值继续透传给 `updateProfile`。本轮仅接受 `home | center` 两个合法值，其余值统一按缺失处理。

### 2. 成功回跳规则

`updateProfile` 根据 `from` 参数决定回跳目标：

- `from=home` → `/${locale}?profileUpdated=true`
- `from=center` → `/${locale}/my-events?profileUpdated=true`
- 无来源或异常来源 → `/${locale}/my-events?profileUpdated=true`

### 3. 失败处理规则

失败时仍保留在编辑页，并保留规范化后的来源参数：

- `/${locale}/profile?from=<normalizedFrom>&error=...`

其中：
- 原始来源为 `home` 时继续保留 `from=home`
- 原始来源为 `center` 时继续保留 `from=center`
- 无来源或异常来源时，按默认来源 `center` 处理

原因：失败属于继续修正表单的场景，不应打断到首页或个人中心，同时需要保证下一次提交仍然遵循“从哪进回哪去”的规则。

### 4. 成功反馈规则

成功提示出现在回跳落点页，而不是编辑页：

- 回首页：提示“个人画像已完善，可获得更准确的推荐”
- 回个人中心：提示“个人画像已更新”

建议使用语义化参数：
- `profileUpdated=true`

本轮将其定义为“回跳落点页显示成功反馈”，而不是严格的一次性提示。也就是说，只要 URL 上仍保留该参数，页面就继续展示该成功反馈；本轮不额外引入消费后清理 query 的机制。

## 画像完整度统一规则

本轮继续沿用当前最小可用标准：

- `bio`
- `industry`
- `city`

任一缺失即视为“待完善”。

该规则需抽为统一可复用逻辑，供以下页面共同使用：

- 首页
- 个人中心
- 后续其他资料相关入口

本轮不扩展到更多画像字段或复杂完成度评分。

## 强提醒 / 弱提醒策略

本轮不引入数据库字段来记录引导状态，而是收敛为基于 cookie 的轻量实现：

- 首次未完善画像的嘉宾进入首页时显示强提醒样式。
- 首页在展示强提醒后写入一个轻量 cookie，表示该用户已看过强提醒。
- 后续仍未完善画像时，首页读取该 cookie 并降级显示弱提醒样式。
- 一旦画像完善，首页隐藏提醒，个人中心固定入口继续保留。

选择 cookie 而不是 query 或本地标记的原因：

- 首页当前是服务端页面，cookie 更符合现有服务端渲染模式。
- query 只能表达单次跳转来源，不能稳定表达“已看过强提醒”的状态。
- 本地标记会引入服务端与客户端渲染不一致问题，本轮避免增加额外客户端状态复杂度。

本轮不追求跨设备或长期精确的 onboarding 状态管理，只需先稳定区分强提醒与弱提醒。

## 文案与语义设计

### 首页引导文案方向

文案要表达两层价值：

1. 完善画像后可获得更准确的活动推荐。
2. 主办方可以更好地判断是否邀请该嘉宾。

避免把个人画像表达成普通资料补录任务。

### 个人中心画像卡片文案方向

- 标题：个人画像
- 状态：待完善 / 已完善
- 描述：用于推荐和邀请匹配
- 按钮：去完善 / 编辑画像

### 页面语义升级

虽然路由仍保留 `/my-events`，但页面标题、描述和区块命名需要按角色做最小分化，减少“嘉宾进入我的活动页却找不到个人资料”的认知偏差：

- 嘉宾：页眉主标题升级为“个人中心 / Guest Center”语义，并把个人画像放在首个主模块。
- 主办方：保留“工作台 / Organizer Console”或“我的活动”语义，继续突出活动管理。
- Navbar 用户名入口保持不变，但落地页标题需与角色语义一致。

本轮允许继续复用现有消息命名空间，但需要补齐角色化标题和描述文案，避免只改副标题、不改主标题。

- 来源参数解析与回跳辅助逻辑。

## 边界场景

### 1. 来源参数缺失

- 用户直接打开 `/profile`
- 来源参数被用户手动删除

处理：允许正常编辑，保存后默认回个人中心。

### 2. 未登录访问

保留现有登录校验与跳转逻辑，不在本轮更改。

### 3. 保存失败

- 失败时停留在编辑页
- 展示错误提示
- 不跳回来源页

### 4. 用户长期未完善画像

- 首页继续以弱提醒方式保留入口
- 个人中心固定入口始终存在

### 5. 主办方角色

- 不参与首页画像引导主流程。
- 不把画像作为个人中心第一主模块。

### 6. profile 缺失兜底

- 若已登录用户的 `profiles` 记录异常缺失，本轮按“待完善资料用户”兜底处理。
- 首页仅在角色可判断为嘉宾时进入画像引导主流程；若角色缺失，则保守地不进入主办方流程。
- 个人中心仍应提供资料编辑入口，避免异常账户无路可走。

## 非目标

本轮不包含：

- 新建 `/account` 等新路由体系
- 把画像编辑表单直接并入 `/my-events`
- 增加新的数据库字段来记录 onboarding 状态
- 扩展更多画像字段、完成度进度条或画像评分系统
- 重做导航整体结构

## 验证策略

### 手工验证

1. 嘉宾从首页进入编辑页，保存后回首页。
2. 嘉宾从个人中心进入编辑页，保存后回个人中心。
3. 嘉宾画像未完善时：首页显示提醒，个人中心显示固定入口。
4. 嘉宾画像已完善时：首页主提醒隐藏，个人中心仍可编辑。
5. 主办方进入 `/my-events` 时仍以活动管理为主。
6. 保存失败时停留在编辑页并显示错误。

### 自动化验证

- 为画像完整度判断逻辑补最小单测。
- 为来源参数解析与回跳规则补行为测试，至少覆盖 `from=home`、`from=center`、缺失来源三种分支。
- 验证保存失败时是否保留 `from`，确保下一次提交仍然遵循原来源回跳。
- 根据改动范围补充首页、个人中心或表单相关渲染测试，至少覆盖嘉宾与主办方在 `/my-events` 的结构差异。
- 至少验证首页强提醒与弱提醒存在一个可自动化断言的判定行为。
- 至少运行与改动相关的测试和 lint。

## 实施顺序建议

1. 调整 `updateProfile` 的来源参数与回跳机制。
2. 在 `/my-events` 为嘉宾增加顶部个人画像主卡片。
3. 调整首页引导为强提醒 / 弱提醒结构。
4. 同步成功反馈与国际化文案。
5. 运行验证并修正。

## 成功标准

本轮完成后应满足：

1. 个人画像保存成功后不再停留在编辑页，而是回到来源页。
2. 嘉宾在个人中心始终能找到稳定的个人画像入口。
3. 首页只承担引导职责，不再是唯一入口。
4. 嘉宾首次完善、后续修改与长期维护形成闭环。
5. 主办方流程不被本轮改动打断。

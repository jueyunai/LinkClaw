# LinkClaw 用户旅程与验收基线

> 版本：1.1
> 日期：2026-03-18
> 用途：作为当前实现核查、本轮补齐范围和后续测试验收的统一基线

---

## 文档说明

本文档不再把“理想能力”和“当前已实现能力”混写，而是按以下状态标记：

- **已实现**：当前代码已具备
- **本轮补齐**：已确认纳入当前开发范围
- **规划中**：暂不作为本轮验收要求
- **可选**：后续可根据产品决策补充

---

## 一、角色定义

| 角色 | 描述 | 核心目标 |
|------|------|----------|
| **嘉宾（Guest）** | 寻找并参加活动的个人用户 | 发现感兴趣的活动、报名参与、建立人脉 |
| **主办方（Organizer）** | 发布和管理活动的组织/个人 | 发布活动、精准触达目标嘉宾、管理报名 |

## 二、嘉宾（Guest）用户旅程

### 场景 1：注册与画像完善

| 步骤 | 用户行为 | 预期结果 | 当前状态 | 说明 |
|------|----------|----------|----------|------|
| 1.1 | 访问首页 `/zh` 或 `/en` | 看到活动列表和登录/注册入口 | 已实现 | 支持双语路由切换 |
| 1.2 | 点击“注册”进入 `/auth/register` | 显示注册表单 | 已实现 | 包含邮箱、密码、昵称、角色选择 |
| 1.3 | 选择角色并提交注册 | 注册成功，进入验证链路 | 本轮补齐 | 本轮要求显式补建 `profiles`，覆盖邮箱注册与 OAuth 首次登录补建 |
| 1.4 | 完成验证并登录 | 登录成功，进入首页 | 已实现 | 已有 session 建立与导航状态切换 |
| 1.5 | 首次登录后看到资料补全提示 | 首页提示完善资料并可进入 `/profile` | 本轮补齐 | 不做强制跳转，采用轻引导 |
| 1.6 | 填写 Bio、行业、城市 | 保存成功 | 已实现 | `profiles` 更新 `bio/industry/city` |

**验收关注点**
- 新注册用户或首次 OAuth 登录用户都能获得最小 `profiles` 记录
- 缺少 `bio/industry/city` 或缺失 `profile` 记录时，首页显示补全引导

## 五、页面路由速查表

| 页面 | 路径 | 角色权限 | 核心功能 |
|------|------|----------|----------|
| 首页 / 活动发现 | `/[locale]/` | 全部 | 浏览活动、推荐活动、资料补全引导 |
| 登录 | `/[locale]/auth/login` | 未登录 | 用户认证 |
| 注册 | `/[locale]/auth/register` | 未登录 | 创建账户 |
| 邮箱验证 | `/[locale]/auth/verify-email` | 已注册 | 验证邮箱 |
| 个人画像 | `/[locale]/profile` | 已登录 | 编辑个人资料 |
| 活动详情 | `/[locale]/events/[id]` | 全部 | 查看活动、报名、查看报名/邀请状态 |
| 发布活动 | `/[locale]/events/new` | 主办方 | 创建新活动 |
| 活动管理 | `/[locale]/events/[id]/manage` | 主办方（所有者） | 管理报名、邀请嘉宾 |
| 我的活动 | `/[locale]/my-events` | 已登录 | 嘉宾：已报名 / 收到邀请；主办方：已发布活动 |

## 七、验收基线

### 必测主链路
1. 注册 → 验证 / 登录 → 获得最小 `profiles` 记录
2. 已登录用户在资料不完整时看到首页引导
3. 嘉宾报名后能看到真实状态
4. 嘉宾在 `/my-events` 看到邀请理由并处理邀请
5. 主办方能继续正常管理报名和邀请

### 非本轮验收项
- 取消报名
- 管理页统计看板
- 推荐系统大范围重构
- 权限架构重构

# 代码诊断报告

> 日期：2026-04-24
> 范围：全站核心流程（认证、活动、报名、管理后台）

---

## 🔴 严重 Bug（流程阻塞）

### 1. OAuth 新用户没有创建 Profile — 全站崩溃

**文件：** `src/app/api/auth/guancha/callback/route.ts`

**现象：** 通过观猹 OAuth 注册的新用户只调用了 `ensureGuanchaIdentity()`，但从未调用 `ensureProfileExists()`。首页、活动详情页、个人中心等几乎所有页面都依赖 `profiles` 表查询，新 OAuth 用户登录后会立即遇到空数据或页面异常。

**对比：** `src/app/[locale]/auth/actions.ts` 中的 `register()` 函数正确调用了 `ensureProfileExists()`，但 OAuth 回调遗漏了。

**修复方向：** 在 OAuth 回调创建新用户后，调用 `ensureProfileExists(createData.user.id, 'guest', userInfo.nickname)`。

---

### 2. OAuth 登录后 redirect 丢失

**文件：** `src/app/[locale]/auth/actions.ts` → `startAuth()`

**现象：** `startAuth()` 设置了 `guancha_oauth_locale` cookie，但没有设置 `guancha_oauth_redirect` cookie。回调路由虽然读取了这个 cookie，但它永远是 `undefined`，fallback 到 `'/'`。用户从受保护页面被重定向到登录、选择 OAuth 后，登录成功不会回到原页面。

**修复方向：** 在 `startAuth()` 中从请求参数或 referrer 获取 redirect 目标，写入 `guancha_oauth_redirect` cookie。

---

### 3. 管理页面加载全部嘉宾 — 数据泄露 + 性能炸弹

**文件：** `src/app/[locale]/events/[id]/manage/page.tsx`

**现象：**
```ts
const { data: guests } = await supabase
  .from('profiles')
  .select('id, display_name, bio, industry, city, role')
  .eq('role', 'guest');
```
这会把数据库中所有 guest 角色的用户全部拉出来。用户量增长后会严重拖慢页面，且向单个 organizer 暴露了全站嘉宾信息。

**修复方向：** 改为分页查询或仅查询与当前活动相关的嘉宾；推荐嘉宾列表应由后端 AI 服务按需返回。

---

## 🟠 中等风险

### 4. `updateUserById` 静默失败

**文件：** `src/app/api/auth/guancha/callback/route.ts`

**现象：** OAuth 回调中更新用户元数据用了 fire-and-forget 模式（`.catch(err => console.error(...))`），如果更新失败，用户的昵称/头像不会同步，且没有任何重试机制。

**修复方向：** 改为 `await` 并在失败时记录到错误追踪系统，或增加重试逻辑。

---

### 5. 确定性密码方案的安全隐患

**文件：** `src/lib/auth/guancha.ts` → `getDeterministicPassword()`

**现象：** 用 `HMAC(clientSecret, guanchaUserId)` 生成密码。如果 `GUANCHA_CLIENT_SECRET` 泄露，所有 OAuth 用户的 Supabase 密码都可以被推算出来。

**修复方向：** 改用随机密码 + 仅通过 admin API 管理登录，或为每个用户加入独立盐值。

---

### 6. 登录页未传递 redirect 参数给 OAuth

**文件：** `src/app/[locale]/auth/login/page.tsx`

**现象：** `LoginPage` 从 `searchParams` 读取了 `error`，但没有读取 `redirect`。当 middleware 把未登录用户重定向到 `/auth/login?redirect=xxx` 后，用户选择 OAuth 登录时，`redirect` 参数没有被传递给 `startAuth()`，也就无法写入 cookie。

**修复方向：** 在登录页读取 `redirect` 参数，通过隐藏字段或 `startAuth` 参数传递给 OAuth 流程。

---

### 7. `as never` 类型断言遍布全站

**文件：** 多个 actions.ts 文件

**现象：** 所有 Supabase 写操作都用了 `as never` 绕过类型检查。如果数据库 schema 变更，TypeScript 不会报错，只会在运行时失败。

**修复方向：** 修正 `Database` 类型定义使其与实际 schema 匹配，移除 `as never`。

---

## 🟡 低风险 / 代码质量

### 8. `register()` 暴露原始错误信息

**文件：** `src/app/[locale]/auth/actions.ts`

**现象：** `login()` 有 `getLoginErrorMessage()` 做错误信息翻译，但 `register()` 直接把 `error.message` 展示给用户，可能暴露内部实现细节。

**修复方向：** 为注册流程也添加错误信息映射函数。

---

### 9. admin `updateHunterLevel` 缺少目标用户存在性校验

**文件：** `src/app/[locale]/admin/actions.ts`

**现象：** 虽然 `.eq('role', 'guest')` 限制了只能更新嘉宾，但如果 `targetUserId` 不存在，Supabase 不会报错（update 0 rows），admin 会看到"成功"提示但实际没有任何变更。

**修复方向：** 检查 update 返回的行数，为 0 时提示"用户不存在"。

---

### 10. 环境变量缺少启动时校验

**文件：** `src/lib/auth/guancha.ts`、`src/lib/supabase/middleware.ts`

**现象：** `getGuanchaConfig()` 和 `getSupabaseEnv()` 在运行时才检查环境变量，部署时如果漏配不会立即发现。

**修复方向：** 在 `next.config.ts` 或应用启动阶段统一校验必需环境变量。

---
